# image-generation

这个 Skill 用于根据文本描述生成图片。与依赖外部 API 的方案不同，本技能零密钥：
不配置、不读取、不传递任何 API Key，所有生成都通过宿主环境内置的图片生成能力完成。
技能在会话内首次被调用时，必须先通过「生效前置检查」，确认当前模型支持图片输出；
检查通过前，本技能不得生效。

## 何时调用

- 用户要求"根据描述生成图片"
- 用户需要"AI 绘画"或"文生图"
- 用户希望"创建一张图片"
- 用户需要生成特定风格的图像（写实、艺术、抽象等）

## 不可调用场景

- 生效前置检查未通过（当前模型/会话不支持图片输出）
- 用户要求生成视频或动画
- 用户需要生成 3D 模型
- 用户明确要求调用某个需要 API Key 的外部图片服务

## 生效前置检查（必须最先执行）

本技能在每个会话中首次被调用时，必须按顺序完成以下两步检查。两步全部通过，
技能才允许生效并继续处理用户的图片请求。

### 第 1 步：工具发现

- 检索当前会话可用的工具（含延迟加载工具），确认存在图片生成工具
  （如 ImageGen、文生图、image generation 类工具）。
- 未找到任何图片生成工具 → 检查失败。

### 第 2 步：探针验证

- 使用一个最小提示词（例如 "a single red circle on a white background"）
  实际调用一次图片生成。
- 校验返回结果是真实图片（本地图片文件或可访问的图片 URL），而不是文本说明、
  错误信息或占位内容。
- 调用失败、无图片产出、或仅返回文字 → 检查失败。

### 检查结论处理

| 结果 | 行为 |
| --- | --- |
| 两步均通过 | 技能在当前会话生效，继续执行用户的图片请求 |
| 任一步失败 | 技能不生效：明确告知用户"当前模型/会话不支持图片输出"，停止流程 |
| 模型或会话发生切换 | 重新执行前置检查 |

- 每个会话只做一次前置检查，通过后无需在每次生成前重复探针。
- 探针产生的图片是检查副产品，不作为用户交付物。

### 检查失败时的禁令

- 禁止降级：不得用占位图、示意图、mock 数据或纯文字描述冒充生成结果。
- 禁止绕行：不得引导用户配置 API Key、token 或任何密钥来"恢复"能力；
  本技能不存在密钥配置路径。
- 如实报告：告诉用户失败发生在哪一步、原因是什么，并停止使用本技能。

## 无密钥约束

- 本技能不使用、不读取、不申请任何 secret：无 API Key、无 token、
  无 `.env` 文件、无 BASE_URL 配置。
- 所有图片生成都通过宿主环境已登录、已授权的内置图片生成能力完成。
- 不得在提示词、脚本或文档中引入任何需要密钥的外部服务调用。

## 使用方式

### 基础使用

1. 执行生效前置检查（仅会话首次调用时）。
2. 收集用户对图片内容、风格、构图的要求；描述不完整时按「提示词建议」补全，
   关键信息缺失（如主体不明）时先向用户询问。
3. 调用当前会话的图片生成工具，传入完整提示词。
4. 校验产出为真实图片后交付：保存为文件或展示图片。

### 参数说明

| 参数 | 说明 | 默认值 | 必填 |
|------|------|--------|------|
| prompt | 图片描述文本，包含主体、风格、色彩、构图、氛围 | 无 | 是 |
| size | 期望的尺寸或比例；以宿主图片生成工具实际支持的取值为准 | 工具默认值 | 否 |
| count | 生成张数 | 1 | 否 |

工具不支持某个参数（如自定义尺寸）时，直接省略该参数，不要伪造或空转重试。

## 输出要求

- 成功时返回真实生成的图片（本地文件路径或图片 URL）。
- 失败时如实返回失败原因和失败环节，不生成替代性内容。
- 交付引用生成时间时，使用 UTC+8，格式 `YYYY-MM-DD HH:mm:ss`。

## 错误处理

| 错误 | 处理建议 |
|------|----------|
| 前置检查失败 | 告知用户当前模型不支持图片输出，停止使用本技能 |
| 图片工具调用报错 | 原样转述错误信息；可微调提示词重试一次，仍失败则停止 |
| prompt 为空或主体不明 | 先向用户询问图片描述，不要自行编造主体 |
| 内容被安全策略拒绝 | 调整提示词后重试一次；连续被拒则向用户说明并停止 |
| 工具不支持请求的参数 | 省略该参数使用默认值，并向用户说明 |

## 示例场景

### 场景 1：生成默认图片
```text
用户："画一只在阳光下睡觉的橘猫。"
流程：前置检查（会话首次）→ 通过 → 以完整提示词调用图片生成工具 → 交付图片。
```

### 场景 2：生成指定风格与构图的图片
```text
用户："来一张赛博朋克风格的城市夜景，俯视角度。"
流程：前置检查已通过 → 按提示词建议补全细节 → 生成 → 交付图片。
```

### 场景 3：前置检查不通过
```text
用户："帮我生成一张海报图。"
流程：工具发现未找到图片生成工具（或探针未产出真实图片）
     → 技能不生效 → 告知用户当前模型不支持图片输出，停止流程。
     不提供占位图，不引导用户配置任何 API Key。
```

## 提示词建议

为了获得更好的生成效果，建议在 prompt 中包含：

1. **主体描述**：明确描述图片的主要内容
2. **风格说明**：如"写实"、"油画"、"水彩"、"赛博朋克"等
3. **色彩搭配**：如"暖色调"、"冷色调"、"黑白"等
4. **构图方式**：如"特写"、"远景"、"俯视"等
5. **氛围营造**：如"宁静的"、"充满活力的"、"神秘的"等

示例提示词：
- "一只橘色的猫咪，写实风格，温暖的阳光，特写镜头，宁静的氛围"
- "未来城市，赛博朋克风格，霓虹灯光，夜景，俯视角度"
- "抽象几何图案，鲜艳色彩，现代艺术风格"
